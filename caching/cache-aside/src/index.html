Cache-aside

Every product lookup asks Redis first. If Redis has it, that's a HIT and the answer comes back fast. If not, that's a MISS: the server asks Postgres (slow on purpose, 1–2s), then saves the answer in Redis for 30 seconds. See caching/README.md.

2. The cache lies to you (stale data)


Load the product first so it's cached. Then "forget the cache", load it again, and you'll see the old price. "Look at both ends" shows what Postgres says, what Redis says, and how many seconds until Redis forgets its copy.

3. Everyone rushes in at once (stampede)

Empties the cache for product 1, then sends that many requests for it at the same instant. Without the fix they all miss and all go to the database. With coalescing, only the first one does and the rest wait for its answer.
